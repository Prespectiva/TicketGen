Описание применения
===================

Раздел составлен по структуре ГОСТ 19.502-78 «Описание применения»:
назначение программы, условия применения, описание задачи, входные
и выходные данные.

Назначение программы
--------------------

TicketGen автоматизирует подготовку экзаменационных и зачётных билетов,
вариантов контрольных и самостоятельных работ. Вручную такой комплект
собирается долго, а билеты получаются разной трудности. Программа решает
обе проблемы: преподаватель один раз заполняет банк вопросов и описывает
состав билета правилами, а программа за секунды составляет нужное число
разных билетов с одинаковым суммарным баллом.

Основные возможности:

* банк вопросов с делением на предметы и темы, тремя уровнями сложности
  и тремя типами вопросов (теория, задача, практика);
* поиск и фильтры по тексту, предмету, теме, сложности и типу;
* импорт вопросов из CSV-файла с отчётом об ошибочных строках;
* шаблоны билетов из правил «тема + сложность + количество вопросов»
  с автоматическим расчётом балла;
* генерация серии до 100 билетов, режим «без пересечений» и повторяемый
  результат при одинаковом seed;
* просмотр серии, замена вопроса в готовом билете, сводная ведомость;
* экспорт билетов, ответов и ведомости в DOCX и PDF, оформление билета
  эмблемой, строкой для ФИО студента и местом для подписи;
* выгрузка билетов в Moodle (форматы Moodle XML и GIFT);
* резервная копия базы при каждом закрытии программы.

Ограничения области применения:

* программа однопользовательская: база ``tickets.db`` лежит рядом
  с программой и не рассчитана на одновременную работу нескольких людей;
* вопросы открытые (ответ пишет студент): программа не проверяет ответы
  и не проводит тестирование;
* программа работает без интернета и не передаёт данные в сеть.

Описание задачи
---------------

Дано: банк вопросов, где у каждого вопроса есть тема и уровень сложности,
а у уровня сложности есть вес в баллах (лёгкий — 1, средний — 2,
сложный — 3). Шаблон билета задаёт набор правил: из темы *T* со
сложностью *D* взять *k* вопросов.

Нужно составить *m* билетов, для которых выполняются условия:

1. в каждом билете ровно столько вопросов каждой темы и сложности,
   сколько указано в правилах, и внутри билета вопросы не повторяются;
2. суммарный балл каждого билета одинаков и равен
   S = Σ(kᵢ · wᵢ), где wᵢ — вес сложности правила;
3. два билета с одинаковым набором вопросов не допускаются;
4. в режиме «без пересечений» каждый вопрос попадает только в один
   билет серии;
5. одинаковый seed (число для генератора случайных чисел) при том же
   шаблоне и банке даёт ту же серию.

Метод решения. Для каждого правила отбираются активные вопросы нужной
темы и сложности. До генерации проверяется, что их хватит: в обычном
режиме нужно n ≥ k, в режиме без пересечений n ≥ m · k, а число
возможных разных билетов (произведение C(n, k) по правилам) должно быть
не меньше m. Затем каждый билет собирается случайной выборкой без
повторений из каждой группы. Если такой набор уже был в серии, выборка
повторяется (до 1000 попыток). Подробно алгоритм описан в модуле
:mod:`ticketgen.logic.generator`.

Входные и выходные данные
-------------------------

**Входные данные:**

* вопросы, введённые в окне вопроса: предмет, тема, сложность, тип,
  текст вопроса и эталонный ответ;
* CSV-файл с вопросами. Разделитель ``;`` или ``,``, кодировка UTF-8
  или Windows-1251, столбцы
  ``дисциплина;тема;сложность;тип;вопрос;ответ`` (первый столбец можно
  назвать «предмет»). Пустой шаблон сохраняет кнопка «Шаблон CSV»,
  пример с ошибками лежит в ``examples/questions_example.csv``;
* параметры шаблона: название, заголовок билета, предмет, правила,
  оформление (вид документа, эмблема PNG/JPG/BMP/GIF, подписи);
* параметры генерации: шаблон, число билетов (1–100), seed, режим
  без пересечений.

**Выходные данные:**

* серия билетов в базе данных: её можно открыть, изменить и выгрузить
  повторно;
* файлы в папке ``export``:

  .. list-table::
     :header-rows: 1
     :widths: 35 65

     * - Файл
       - Содержимое
     * - ``<имя>_билеты.docx`` / ``.pdf``
       - билеты без ответов, по два на листе A4 с линией отреза
     * - ``<имя>_ответы.docx``
       - таблица «билет — номер вопроса — эталонный ответ»
     * - ``<имя>_ведомость.docx``
       - для каждого билета: id вопросов, темы и суммарный балл

* файл для Moodle (``.xml`` или ``.txt`` в формате GIFT): каждый билет
  становится категорией вопросов типа «Эссе»;
* резервные копии базы ``backup/tickets_ГГГГММДД_ЧЧММСС.db``
  (хранятся пять последних).
