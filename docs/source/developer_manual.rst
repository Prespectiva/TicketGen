Руководство разработчика
========================

Руководство нужно разработчику, который будет сопровождать или дорабатывать
TicketGen. Основные разделы идут по ГОСТ 19.503-79 «Руководство системного
программиста»: общие сведения, структура, настройка, проверка,
дополнительные возможности и сообщения. В конце описано, как новому
разработчику быстро войти в проект.

Общие сведения о программе
--------------------------

* Назначение и функции описаны в разделах :doc:`overview` и
  :doc:`functionality`.
* Язык — Python 3.10–3.13. Интерфейс — PyQt6, база — SQLite через
  модуль ``sqlite3`` стандартной библиотеки, экспорт — python-docx
  (DOCX) и reportlab (PDF).
* Зависимости и виртуальное окружение — Poetry, точные версии
  зафиксированы в ``poetry.lock``.
* Качество кода — black (форматирование, строка до 88 символов), flake8
  (стиль и ошибки), pre-commit (обе проверки перед каждым коммитом).
* Тесты — pytest, покрытие — coverage.py через pytest-cov, сборка
  исполняемого файла — PyInstaller.
* Репозиторий — https://github.com/Prespectiva/TicketGen. Основная ветка
  ``main``, работа идёт в отдельных ветках через Pull Request.

Структура программы
-------------------

Слои, паттерны, схема базы и внутренний API описаны в разделе
:doc:`architecture`, справочник по модулям — в :doc:`api/index`. Ключевые
точки кода, с которых удобно начинать чтение:

.. list-table::
   :header-rows: 1
   :widths: 38 62

   * - Файл
     - Что в нём
   * - ``main.py``
     - запуск: QApplication, тема, подключение к базе, главное окно
   * - ``ticketgen/controllers/app_controller.py``
     - все действия пользователя: по методам контроллера видно, что
       умеет программа
   * - ``ticketgen/logic/generator.py``
     - алгоритм генерации серии
   * - ``ticketgen/data/database.py``
     - схема базы и миграция столбцов оформления
   * - ``ticketgen/data/repositories.py``
     - весь SQL программы
   * - ``ticketgen/logic/exporters.py``
     - сборка документа из блоков и экспортёры DOCX/PDF
   * - ``ticketgen/views/main_window.py``
     - как собраны вкладки и как они связаны сигналами
   * - ``tests/conftest.py``
     - фикстуры: база в памяти и база с тестовыми данными

Правила, которых держится код:

* окна не содержат SQL и расчётов и обращаются только к контроллеру;
* SQL пишется только в репозиториях и только с параметрами ``?``;
* ошибка, которую должен увидеть пользователь, — это
  ``TicketGenError`` с понятным русским текстом;
* долгие операции выполняются в ``BackgroundWorker``, виджеты трогает
  только главный поток;
* у каждого модуля, класса и функции есть docstring на русском в стиле
  Google (``Args``, ``Returns``, ``Raises``): из них собирается
  справочник API.

Настройка программы
-------------------

Подготовка среды разработки
~~~~~~~~~~~~~~~~~~~~~~~~~~~

1. Установите Python 3.10–3.13 (при установке отметьте «Add python.exe
   to PATH») и Git.
2. Склонируйте репозиторий и установите зависимости::

      git clone https://github.com/Prespectiva/TicketGen.git
      cd TicketGen
      py -m pip install poetry
      py -m poetry install

   Poetry создаст виртуальное окружение и поставит туда программу, тесты,
   black, flake8, pre-commit, coverage и PyInstaller. Если нужно, чтобы
   окружение лежало в папке проекта (``.venv``), выполните перед
   установкой ``py -m poetry config virtualenvs.in-project true``.
3. Включите хуки проверки перед коммитом::

      py -m poetry run pre-commit install

4. В VS Code выберите интерпретатор из окружения Poetry
   (``Ctrl+Shift+P`` → «Python: Select Interpreter»).

Запуск
~~~~~~

::

   py -m poetry run python -m ticketgen.seed_data   # демонстрационные данные
   py -m poetry run python main.py

``seed_data`` заполняет базу четырьмя темами, 96 вопросами и шаблоном
«Экзамен ОАиП, 2 курс». Запускать его нужно на пустой базе.

Настройки путей
~~~~~~~~~~~~~~~

Все пути задаёт :class:`~ticketgen.config.AppConfig`:

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - Параметр
     - Значение
   * - ``base_dir``
     - папка проекта, а в собранной программе — папка с
       ``TicketGen.exe`` (признак ``sys.frozen``)
   * - ``db_path``
     - ``base_dir/tickets.db``
   * - ``backup_dir``
     - ``base_dir/backup``
   * - ``export_dir``
     - ``base_dir/export``
   * - ``backups_to_keep``
     - 5 — сколько резервных копий хранить

Веса уровней сложности хранятся в таблице ``tbl_difficulty`` и меняются
методом ``DifficultyRepository.update_weight``.

Проверка программы
------------------

Автоматические тесты
~~~~~~~~~~~~~~~~~~~~

::

   py -m poetry run pytest
   py -m poetry run pytest --cov=ticketgen --cov-report=term-missing --cov-report=html

Каждый тест получает свою базу SQLite в памяти (фикстуры ``db`` и
``filled_db`` в ``tests/conftest.py``), рабочий ``tickets.db`` не
затрагивается. Отчёт о покрытии открывается из ``htmlcov/index.html``.
Слой ``views`` исключён из подсчёта покрытия (раздел
``[tool.coverage.run]`` в ``pyproject.toml``) и проверяется вручную.

.. list-table::
   :header-rows: 1
   :widths: 35 65

   * - Файл
     - Что проверяет
   * - ``test_repositories.py``
     - CRUD, фильтры, запрет удаления используемых записей, защита
       от SQL-инъекций, поиск без учёта регистра
   * - ``test_generator.py``
     - уникальность билетов, равный балл, повтор по seed, режим без
       пересечений, нехватка вопросов, скорость (30 билетов из 1000
       вопросов)
   * - ``test_scoring.py``
     - формула балла, проверка правил, число возможных билетов
   * - ``test_csv_importer.py``
     - разбор CSV, ошибочные строки, неверный заголовок, файл
       в Windows-1251
   * - ``test_exporters.py``
     - создание файлов, заголовок без метки ``{N}`` в ответах
       и ведомости, темы со счётчиком
   * - ``test_subjects_and_style.py``
     - предметы, оформление билета, миграция старой базы, шаблон CSV,
       таблица ответов, Moodle XML и GIFT, два билета на листе
   * - ``test_app_controller.py``
     - интеграционные тесты контроллера на настоящей базе
   * - ``test_views_helpers.py``
     - вспомогательные функции интерфейса без окон

Качество кода
~~~~~~~~~~~~~

::

   py -m poetry run black --check .
   py -m poetry run flake8

Системная проверка
~~~~~~~~~~~~~~~~~~

Скрипт ``scripts/system_check.py`` проверяет показатели из ТЗ на временной
базе (банк до 10 000 вопросов, время генерации и экспорта, равный балл,
режим без пересечений, импорт 100 вопросов, защита от SQL-инъекций,
резервная копия) и печатает таблицу «требование → результат»::

   py -m poetry run python scripts/system_check.py

Ручная проверка
~~~~~~~~~~~~~~~

После изменений в окнах запустите программу и пройдите сценарий: импорт
CSV → шаблон → генерация 30 билетов → замена вопроса → экспорт в DOCX
и PDF → открытие файлов в Word → закрытие программы (в ``backup``
появилась копия, в терминале нет ошибок).

Дополнительные возможности
--------------------------

Сборка TicketGen.exe
~~~~~~~~~~~~~~~~~~~~

Запустите ``build.bat`` из корня проекта. Скрипт ставит зависимости,
очищает прошлую сборку, собирает один файл без консоли с иконкой и
папкой иконок внутри и копирует в ``dist`` тестовую базу и
``examples``. Результат — ``dist\TicketGen.exe``. Папку ``dist`` можно
переносить целиком.

Сборка этой документации
~~~~~~~~~~~~~~~~~~~~~~~~

Sphinx и тема ставятся в окружение проекта один раз::

   py -m poetry add --group dev sphinx sphinx-rtd-theme

Сборка HTML::

   py -m poetry run sphinx-build -b html docs/source docs/build/html

Результат открывается из
``docs/build/html/index.html``. Окна PyQt6 и библиотеки экспорта для
сборки не нужны: в ``conf.py`` они заменены заглушками
(``autodoc_mock_imports``). После изменения docstrings документацию
нужно пересобрать, предупреждения Sphinx лучше исправлять сразу.

Как добавить формат экспорта
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

1. В ``ticketgen/logic/exporters.py`` создайте наследника
   ``BaseExporter`` с атрибутом ``extension`` и методом
   ``save(blocks, path)``. Блоки — кортежи ``(вид, значение)``,
   их виды перечислены в начале модуля.
2. Зарегистрируйте класс в ``ExporterFactory._exporters``.
3. Добавьте переключатель формата в ``ExportDialog``
   (``views/dialogs.py``) и тест в ``tests/test_exporters.py``.

Как добавить столбец в базу
~~~~~~~~~~~~~~~~~~~~~~~~~~~

У пользователей уже есть ``tickets.db`` со старой схемой. Поэтому столбец
добавляется в ``CREATE TABLE`` в ``SCHEMA`` и в словарь вида
``TEMPLATE_STYLE_COLUMNS``. При открытии старой базы метод
``_add_missing_columns`` допишет его командой ``ALTER TABLE`` со
значением по умолчанию. Затем поле добавляется в сущность (``domain``),
в чтение и запись репозитория и в тест миграции.

Работа с Git
~~~~~~~~~~~~

* Каждая задача — отдельная ветка от ``main``: ``feature/…`` для новых
  функций, ``fix/…`` для исправлений, ``docs/…`` для документации.
* Коммит — одно законченное изменение, сообщение по-русски описывает,
  что сделано.
* Ветка отправляется на GitHub и сливается в ``main`` через Pull Request
  после проверки: тесты, black и flake8 проходят.
* Найденные ошибки и идеи заводятся в разделе Issues репозитория
  с меткой важности.

Сообщения системному программисту
---------------------------------

.. list-table::
   :header-rows: 1
   :widths: 42 58

   * - Сообщение
     - Причина и решение
   * - ``ModuleNotFoundError: No module named 'PyQt6'``
     - программа запущена не из окружения Poetry. Запускайте через
       ``py -m poetry run …`` или выберите интерпретатор окружения в VS Code
   * - ``pyproject.toml changed significantly since poetry.lock was last generated``
     - зависимости в ``pyproject.toml`` поменяли вручную. Выполните
       ``py -m poetry lock`` и ``py -m poetry install``
   * - pre-commit не даёт сделать коммит
     - black переформатировал файлы или flake8 нашёл ошибку. Добавьте
       исправленные файлы (``git add``) и повторите коммит
   * - ``sqlite3.OperationalError: no such column …``
     - новый столбец не добавлен в ``TEMPLATE_STYLE_COLUMNS``, и старая
       база его не получила (см. «Как добавить столбец в базу»)
   * - ``RuntimeError: wrapped C/C++ object … has been deleted``
     - код обращается к виджету, который Qt уже удалил (обычно при
       закрытии окна). Проверяйте объект через ``sip.isdeleted``
   * - ``QThread: Destroyed while thread is still running``
     - на объект потока не осталось ссылок. Запускайте фоновые задачи
       только через ``BackgroundWorker.start()``
   * - Sphinx: ``WARNING: … Unexpected indentation``
     - в docstring перед списком или блоком нет пустой строки
   * - Sphinx: ``no theme named 'sphinx_rtd_theme'``
     - тема не установлена. Поставьте ``sphinx-rtd-theme`` (тогда
       ``conf.py`` возьмёт её) или соберите со встроенной темой

Как новому разработчику войти в проект
--------------------------------------

Порядок, который позволяет начать работу за один день:

1. **Прочитать.** README, затем в этой документации :doc:`overview`,
   :doc:`architecture` и техническое задание (приложение А отчёта по
   практике). Макет экранов — в Figma, ссылка в README.
2. **Настроить окружение** по разделу «Настройка программы», заполнить
   базу демонстрационными данными и запустить программу. Пройти
   сценарий из :doc:`user_manual` руками: так быстрее всего понять, что
   делает программа.
3. **Запустить тесты** и убедиться, что всё проходит. Это точка отсчёта:
   если после ваших изменений тест упал, виноваты изменения.
4. **Прочитать код по ключевым точкам** из таблицы выше: контроллер →
   генератор → репозитории → одна вкладка. Справочник :doc:`api/index`
   помогает не открывать каждый файл.
5. **Взять небольшую задачу** из Issues, сделать её в отдельной ветке
   с тестом и открыть Pull Request. На ревью проверяются правила кода
   из раздела «Структура программы».

Кто передаёт проект, проверяет, что новый разработчик получил доступ
к репозиторию и к макету в Figma, может собрать ``TicketGen.exe`` на
своём компьютере и знает, где лежат техническое задание и эта
документация.
